## World transforms

[`world_transforms.h`](../src/motorstorm/world_transforms.h) defines caller-owned host matrices, parent indices, root indices and dirty flags. [`world_transforms.cpp`](../src/motorstorm/world_transforms.cpp) evaluates the operation directly on x86, without guest registers, local-store access or instruction dispatch. Parents precede children. A root's translation is restored after the relative hierarchy composition. CPU-only translation scratch is outside this interface.

Compile this operation separately with AVX2/FMA and strict floating-point behavior. Its paired fused products use toward-zero rounding and flush subnormal results. The complete caller MXCSR is restored on normal and exceptional exits. Parent/root ownership, non-finite inputs and arithmetic range violations throw. Callers must use pending host outputs and discard them on failure; the kernel does not provide a transaction over caller buffers. A production adapter must check host instruction support before entering this compiled operation.

Run `python scripts/check_native_world_transforms.py` on an x86-64 AVX2/FMA host with a C++ compiler. Windows accepts `MV_CLANG`; other hosts accept `CXX`. The authored fixture checks independent rounding, fusion, rotation, translation, roots, dirty flags, rejected inputs and caller FP state. A deliberately wrong-rounding implementation must fail the independent product oracle. Build products remain under ignored `build/self-tests/`.

Run `python scripts/check_native_world_properties.py` for the separate
[independent forest properties](NATIVE_WORLD_PROPERTIES.md): 512 fixed-seed forests,
alternate valid orderings, an exact integer point oracle, dirty/no-op/input/FP-state
checks, minimized reproducers and two implementation mutants. This finite-domain
gate complements the dedicated rounding/fusion tests; it does not establish SPU
equivalence, runtime integration or a measured speedup.

## Visibility plane prototype

[Issue 194](https://github.com/robbe1912/motorstorm-mv-recomp/issues/194) owns the next visibility replacement. [`visibility_planes.h`](../src/motorstorm/visibility_planes.h) exposes ordinary box centers, axis directions/extents, planes and eight corners. [`visibility_planes.cpp`](../src/motorstorm/visibility_planes.cpp) constructs ordered corners, then finds the first plane with any corner below the threshold. This tests full containment; it does not prove that every corner is outside. Axis scaling and grouped additions stay separate. Plane evaluation uses a separate x product, fused y/z terms and final offset addition. Both operations use toward-zero/flush semantics, positive-zero corner coordinates, finite/range rejection and exact caller MXCSR restoration. Finite admission tests the IEEE-754 encoding without floating arithmetic or a CRT classification call. Baseline CPU/OS admission is required before entering the separately compiled AVX2/FMA code.

`python scripts/check_native_visibility_planes.py` builds the feature gate and fixture without AVX2 and only the operation with AVX2/FMA. Authored analytic/integer cases, all corner lanes, plane order, boundary equality, signed zero, subnormal, rounding, fusion, range, immutable-input and FP-state checks accompany independent faulty variants. GCC requires a vector dependency before observing arithmetic status; removing it must reproduce the Linux range-check failure. Missing positive-zero normalization also reproduces a bit mismatch against actual original arithmetic.

[`visibility_adapter.cpp`](../src/motorstorm/visibility_adapter.cpp) now targets the complete box/plane entry at `0x83A0`. Its opt-in SPU binding defaults to reference mode (`MS_NATIVE_VISIBILITY=0`). `shadow` compares complete cloned operations; `1` computes typed corners and the plane prefix, materializes all coefficient/cursor/index lanes, then executes one retained decisive original iteration. This preserves the complete scratch ABI instead of assuming caller scratch is dead. Admission checks private inline LS, CPU/OS support, code/data identity, aligned bounded matrix/plane spans, no pending masked event/stalled DMA and inactive diagnostics. It rechecks admission, all link/argument lanes, matrix and plane bytes before changing guest state. Unsupported inputs visibly execute the whole original once. Shadow comparisons normalize only the clone LS backing pointer and preserve the queued normal return; neither clone dispatches the caller or an interrupt. Errors and mismatches are fatal and visible.

Integer bounds on plane components and constructed corners keep skipped nonpreferred dot intermediates below exponent-255 values. Retained comparisons can otherwise raise a host invalid flag even when the preferred boolean agrees. No FP status is synthesized. `python scripts/check_native_visibility_adapter.py` verifies full state, reference/shadow/native paths, exact once-only fallback, changed arguments/matrix/planes, ownership, pending events/DMA and instrumentation against an independently authored ABI model. Preferred-only advancement, wrong coefficient W, early guest writes and omitted numeric admission are rejected; shadow mismatch remains fatal. These fixtures contain no original program payload.

## Build and scene bridge

`python scripts/project.py build --optimize --jobs 1` enables native hierarchy and job-wait bindings by default for the verified original debug-US ELF. Use `--native-visibility` to include the prototype SPU binding (`PORT_NATIVE_VISIBILITY=ON` in CMake); runtime `MS_NATIVE_VISIBILITY=0` remains reference by default. All three `--no-native-world-transforms --no-native-job-wait --no-native-visibility` retain an unbound reference build. Direct CMake configuration uses `PORT_NATIVE_WORLD_TRANSFORMS=ON`, `PORT_NATIVE_JOB_WAIT=ON` and `PORT_TARGET_ELF` pointing to the selected original ELF. This does not change the required PM interpretation for unreplaced work.

[`native_game_binding.py`](../scripts/native_game_binding.py) verifies the original ELF and recovered reference-body identities, copies the selected generated tree into the build directory, and renames only the copied reference definition. A generated forwarding entry preserves direct callers and the registration table; registry-only replacement would miss direct calls. The opt-in visibility binding selects only its verified SPU module. It embeds the original 596-byte leaf and 16-byte permutation table into an exact runtime matcher in the ignored copied TU; original bytes never enter public source. An authored C fixture verifies direct/table/reference calls, both guard windows, restoration when disabled, stale-copy rejection and faulty forwarding/guard controls. Direct SPU calls keep the caller block PC until the original leaf advances; the verified wrapper establishes entry, and the adapter snapshots/rechecks the PC rather than requiring the target address. Actual-AOT and authored full-state cases cover both caller PC 0x9650 and target PC 0x83A0. Other translation units retain their source paths and commands. Changed identities, stale copies and reparse points fail preparation. Original inputs remain read-only. The accepted identities are deliberately narrow; another target or changed generated reference needs verification before its binding is added.

[`scene_hierarchy.cpp`](../src/motorstorm/scene_hierarchy.cpp) converts active, dirty hierarchy inputs into pending host buffers. It checks list/object/layout/data ownership and buffer overlaps before committing world matrices and dirty flags. Inactive, clean and empty work avoids unnecessary matrix access. Topology-dirty or unsupported numeric inputs visibly execute the retained original operation before any native guest writes. The adapter does not change root indices, CPU-only translation scratch, job markers or the original implementation flag. This synchronous game operation replaces its original submission and wait for supported work.

[`native_cpu.cpp`](../src/motorstorm/native_cpu.cpp) is compiled without AVX flags and checks AVX2/FMA, XSAVE/OSXSAVE and enabled XMM/YMM OS state before entering the separately compiled kernel. Unsupported hosts retain original execution. `MS_NATIVE_HIERARCHY=0` selects that reference path in a bound build; `1` enables native work, which is the bound default. Native-operation counters and visible fallback records describe coverage; they are not FPS measurements.

Run `python scripts/check_native_game_binding.py` and `python scripts/check_native_scene.py` for authored binding/transaction tests. They verify unchanged originals and direct/table callers, stable repeated preparation, wrong identities and junction rejection, native commits, whole-list fallback without partial writes, CPU/OS capability requirements, context/FP preservation and reference mode. A bad-commit mutant must fail the independently expected world result.

## Cooperative job dependencies

[Issue 183](https://github.com/robbe1912/motorstorm-mv-recomp/issues/183) owns the native job-marker wait. [`job_wait.h`](../src/motorstorm/job_wait.h) describes a progress source with a claimed-job count and six active lanes. The operation resolves ownership on every poll, reads the claimed count before a full barrier, scans every lane, and returns only when their unsigned minimum reaches the marker. This ordering follows the original instructions; the old decompiler pseudocode placed the barrier differently.

[`job_wait_adapter.cpp`](../src/motorstorm/job_wait_adapter.cpp) reads real producer counters and preserves the actual AOT return register/condition state. It performs no guest writes before completion. Short waits poll briefly; blocked work then uses a per-thread high-resolution Windows timer or a host sleep on other platforms. Unsupported inputs or timer failures visibly execute the retained original operation. There is no fabricated completion or synthetic timeout. `MS_NATIVE_JOB_WAIT=0` selects the original operation in the bound binary; it does not disable native hierarchy work.

Set `MS_NATIVE_JOB_WAIT_PROFILE=1` to time native waits without suspending threads. It is off by default; disabled/reference calls read no profiling clock. Each `[NATIVE_JOB_WAIT_PROFILE] status=complete` record reports the host thread, original return address (`caller`), list object, returned owner, requested marker, completed minimum, poll/cooperation counts and integer `started`, `finished`, `frequency`, `ticks` clock fields. Windows uses raw QPC; other platforms use steady-clock nanoseconds. Clock failures, changed/zero frequency or backward readings emit `status=clock_error` without a duration; completed work is never rerun because a measurement failed. `original` and `reference` statuses identify unmeasured retained execution. Group only validated records with a common clock and explicit observation window. Wait latency includes cooperation and producer scheduling; it is not exclusive CPU time or displayed FPS. Log emission also perturbs execution. Verify caller edges against the selected original before naming a producer. [Issue 188](https://github.com/robbe1912/motorstorm-mv-recomp/issues/188) owns native validation of this diagnostic.

Run `python scripts/check_native_job_wait.py` for authored seven-counter/order/ownership/ABI/reference/error tests, exact caller/owner/timing records, disabled zero-clock behavior and clock failures. Independent premature-completion, barrier-order, missing-cooperation and wrong-duration mutants must fail. The binder regression also compiles independent native/reference callers for two TUs and verifies feature changes restore only known transformed copies, leaving originals and unrelated copy timestamps unchanged.
